# Humanoid Locomotion Control and Sim2Real

<p class="report-meta"><strong>Chao Tan</strong><br>Reinforcement Learning · Adversarial Motion Priors · Sim2Real</p>

> This project develops locomotion control for a custom-built humanoid robot using adversarial motion priors and Sim2Real techniques to produce stable, robust, and human-like motion.

## Overview

Humanoid locomotion requires the controller to track commanded motion while maintaining balance, coordinating many joints, and remaining robust to modeling errors and physical disturbances. This project combines **reinforcement learning (RL)**, **adversarial motion priors (AMP)**, and **Sim2Real deployment** to address that problem on a custom-built humanoid robot.

The demonstrated capabilities include:

- stable walking and running behaviors;
- robust execution under variations in the operating conditions;
- human-like motion encouraged by adversarial motion priors;
- simulated validation before hardware deployment; and
- Sim2Real deployment on a custom-built humanoid robot.

## Control framework

The system is organized around a closed-loop locomotion pipeline:

1. A motion command specifies the desired locomotion behavior, such as walking or running.
2. The policy observes the current robot state together with the commanded motion.
3. The policy produces actions for coordinating the humanoid's joints.
4. Task rewards encourage stable locomotion and command tracking.
5. AMP supplies a learned motion-style signal that encourages the generated behavior to resemble reference motion.
6. The resulting commands are executed in simulation or sent through the hardware control interface.
7. Robot observations close the loop for the next control step.

The control objective therefore balances two requirements: completing the locomotion task reliably and maintaining a natural motion style. Training in simulation makes it possible to explore a wide range of states before transferring the learned controller to physical hardware.

## Adversarial motion priors

AMP provides a data-driven way to encourage human-like movement without manually specifying every stylistic feature. A discriminator learns to distinguish reference motion transitions from transitions generated by the policy. Its output is converted into a style reward during policy training.

The overall learning signal can be viewed conceptually as:

`task reward + motion-style reward`

The task component promotes balance, velocity tracking, and efficient control. The AMP component promotes motion characteristics that are consistent with the reference data. Combining them allows the policy to optimize locomotion performance while avoiding visibly unnatural solutions that can still satisfy a purely task-based objective.

## Reinforcement learning

The reinforcement-learning component is trained in simulation, where a large number of interactions can be collected safely. The policy maps robot observations and motion commands to control actions or corrective terms.

The reinforcement-learning objective is centered on the behaviors required for locomotion:

- tracking commanded motion;
- maintaining an upright and stable posture;
- producing smooth, physically plausible actions;
- coordinating joints through gait changes;
- producing motion consistent with the AMP style signal; and
- recovering from variations not represented perfectly in simulation.

The resulting policy is optimized for both reliable task execution and human-like movement. This learned feedback behavior provides the adaptability needed for walking and running on the custom platform.

## Sim2Real deployment

Simulation provides a controlled environment for training and testing before the policy is transferred to hardware. The Sim2Real stage focuses on reducing the gap between simulated and physical execution in several practical areas:

- consistent joint ordering, units, limits, and action scaling;
- observation and command timing;
- actuator and contact-model mismatch;
- conservative command limits and safe initialization; and
- staged validation from simulation to supported hardware tests.

The project video shows both simulated locomotion and deployment on the custom-built physical humanoid platform. This staged workflow allows controller behavior to be checked before real-world execution and makes deployment failures easier to diagnose.

## Current scope and next steps

The current project establishes an end-to-end AMP locomotion and deployment workflow. Natural extensions include quantitative tracking and stability benchmarks, disturbance-recovery tests, terrain variation, reduced external support during deployment, and broader evaluation across robot platforms.
